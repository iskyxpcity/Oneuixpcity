## 已核对

1. 设置界面的常用动作 ID（如 `back`、`home`、`wifi`）与运行时分发表常量相符，暂未发现它们整体错配。
2. 全局手势处理顺序为先触发触觉反馈、再执行动作；因此触觉有效本身不能证明系统动作成功。
3. 运行时按键/触摸注入原先只使用 `InputManager.getInstance()` 客户端接口。测试分支现改为优先尝试系统服务进程中已捕获的 `InputManagerService`，失败后回退到客户端接口，并继续把最终异常交给现有动作错误处理路径。
4. 该改动重点覆盖依赖输入事件注入的返回、主页、最近任务、媒体键、截图回退以及滚动手势，不代表 Wi-Fi、蓝牙、移动数据、相机/录屏、应用启动等全部动作已经通过设备验证。
